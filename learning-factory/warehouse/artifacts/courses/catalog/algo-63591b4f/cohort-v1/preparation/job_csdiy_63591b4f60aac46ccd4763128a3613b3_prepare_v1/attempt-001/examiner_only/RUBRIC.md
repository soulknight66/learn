## Examiner test matrix

At minimum, examiner-controlled checks should include:

- `UnionFind(0)` reports zero sites and zero components; every attempted site query fails by index.
- `UnionFind(1)` reports one component and size one; self-union returns false and changes nothing.
- Mixed unions on at least eight sites verify both merge directions, transitive equivalence, duplicate returns, root-independent sizes, and exact component-count decrements.
- Invalid indices `-1` and `siteCount` are exercised for `find`, `connected` in both argument positions, `union` in both positions, and `componentSize`; observable state is unchanged afterward.
- Two instances receive different operations and remain independent.
- A deterministic reference model compares union return values, equivalence of every site pair, every component size, and component count after each operation.
- Milestone inputs cover `n=0` and `n=1`, empty streams, connectivity at the first/middle/last event, repeated and self events, and a valid disconnected result.
- Null matrix, null row, short row, long row, and both low and high invalid endpoints are rejected. Put each malformed case both before and after a prefix that would otherwise suffice.
- Snapshot the outer event-array references and every row's contents; confirm they are identical after normal and exceptional calls.
- A modest performance sanity case should reject obvious all-site rescans or connectivity recomputation without relying on a fragile wall-clock threshold alone.

Exception assertions may accept a subclass of the required category, but source inspection should confirm deliberate validation rather than incidental array failures.

## Comprehension answer key

### Prompt 1

Accept equivalent precise invariants. Strong answers include at least four of these:

- parent and size storage have one slot per site and every stored parent is a valid site;
- a root is exactly a site whose parent is itself;
- following parent links from any site reaches one root, with no non-root cycle;
- each tree represents exactly one component and two sites are connected exactly when their root is the same;
- the size stored at a root equals the number of sites in that tree; non-root size entries are ignored;
- component count equals the number of roots, begins at `n`, and decreases exactly once per successful merge; and
- path compression changes parent links only to an ancestor/root in the same tree.

Finite acyclic parent chains terminate at self-parent roots. Union joins only roots, so shared-root equivalence is the maintained connectivity relation. Compression shortens a chain without changing its terminal root or component.

### Prompt 2

The expected observable states are:

1. count 7: `{0,1} {2} {3} {4} {5} {6} {7}`
2. count 6: `{0,1} {2,3} {4} {5} {6} {7}`
3. count 5: `{0,1} {2,3} {4,5} {6} {7}`
4. count 4: `{0,1} {2,3} {4,5} {6,7}`
5. count 3: `{0,1,2,3} {4,5} {6,7}`
6. count 2: `{0,1,2,3} {4,5,6,7}`
7. count 1: `{0,1,2,3,4,5,6,7}`
8. count 1: `{0,1,2,3,4,5,6,7}`

The first seven calls return `true`; the eighth returns `false`. The final `componentSize(3)` is 8. Set order and representative numbers are irrelevant.

### Prompt 3

Construction takes `O(n)` time and space. `siteCount()` and `componentCount()` are worst-case `O(1)`. With union by size, an uncompressed parent path has height at most `O(log n)`, so one `find` can take `O(log n)` in the worst case; path compression plus weighting yields the standard `O(α(n))` amortized cost over an operation sequence. `connected` uses two finds; `union` uses finds plus constant root-link/metadata work; `componentSize` uses a find plus a root lookup. Those three have the same amortized scale (and logarithmic single-operation upper bound under weighting), while total storage remains `O(n)`. Do not award full credit for calling these operations strictly worst-case `O(1)`.

### Prompt 4

Compression changes navigation links within one logical component, not component membership. It therefore must not transfer, decrement, or add component size. Only a successful union changes logical component size: add the losing root's size to the winning root and decrement component count once. A non-root size slot is irrelevant after linking.

### Prompt 5

The valid stream first becomes fully connected after the fourth event, so the result is 4; the fifth valid event is redundant. Replacing the final row with a one-element row makes the complete matrix malformed. The contract requires `IllegalArgumentException` even though the first four rows would connect the universe, because structural prevalidation precedes result calculation.

### Prompt 6

Explicit validation prevents accidental array access and prevents a failed public operation from partly changing parent, size, or component count. Suitable tests snapshot counts, sizes, and pairwise connectivity, invoke each method with `-1` and `n` in every argument position, check the exception category, and compare the snapshot afterward. The constructor should be tested with a negative size, and the client should separately test null/malformed structure and invalid endpoints.

### Prompt 7

Accept a label-relabeling model, adjacency plus BFS/DFS, or another simple independent representation. Cases must be reproducible from fixed seeds, apply the same valid operations, and compare union return values, pairwise connectivity, component count, and component sizes (plus client prefix results where applicable). Reusing a parent forest risks reproducing the same fault. Examples of detectable faults include decrementing count on a duplicate union, failing to add root sizes, linking a root in the wrong direction, or returning a nonminimal milestone.

### Prompt 8

Credible anomalies include lost component-count decrements, stale roots, inconsistent root sizes, visibility of partially updated parent/size state, or—in implementations with inconsistent tie decisions—invalid links. Safe boundaries include single-owner confinement or one external lock around complete public operations. A redesign could synchronize/lock operations or use a concurrency-specific structure after defining linearization and performance requirements; merely declaring arrays volatile is insufficient.

### Prompt 9

Union-find is monotone: it records merged components and generally discards the edge history needed to split a component. Removing one connection may change nothing or may divide a component, which cannot be determined from the forest alone. Requirements should cover online versus offline answers, known future events, graph size, update/query ratio, latency, memory, parallelism, whether rebuilding is acceptable, and whether deletions are arbitrary or follow a restricted rollback order. Those answers guide choices such as periodic rebuilds, offline divide-and-conquer with rollback union-find, or a fully dynamic connectivity structure.
