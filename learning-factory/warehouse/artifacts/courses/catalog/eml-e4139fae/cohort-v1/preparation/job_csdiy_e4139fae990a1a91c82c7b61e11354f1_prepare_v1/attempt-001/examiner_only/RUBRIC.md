Confidentiality boundary: examiner-only. Do not copy this rubric, its scoring rules, reference cases, or answer anchors into `student_safe/`.

## Scope and authority

This rubric evaluates only `kickoff_u01_quantization_engineering`. It does not validate an official MIT lab and cannot establish completion of the wider course. The examiner records evidence; only the worker harness validator may promote state.

## Reproduction procedure

From the directory containing `submission/`, first retain the submitted `results.json` as evidence. Then run in a clean, network-disabled Python 3 environment:

```bash
PYTHONPATH=submission python3 -m unittest discover -s submission/tests -v
PYTHONPATH=submission python3 submission/benchmark.py --output submission/results.reproduced.json
```

Inspect changes only within the named output. Compare schemas and deterministic fields between submitted and reproduced results; timing values need not match. Independently import the three public functions and exercise the reference behaviors below. Record command exit status, test count/failures, and artifact hashes with the examiner result.

## Blocking caps

Apply the lowest applicable cap after scoring:

- **49 maximum:** results are fabricated, cannot be generated by the submitted benchmark, or deterministic result fields conflict materially with reproduction.
- **59 maximum:** quantization or either matrix-vector operation is fundamentally incorrect, or the required commands do not execute after a minor path correction.
- **69 maximum:** non-standard dependencies, network retrieval, input mutation, or missing rejection of NaN/infinity is necessary for the submitted solution to work.
- **79 maximum:** no meaningful independent test oracle, fewer than all six benchmark cases, or generated data is labeled as validated/completed by the learner.

A missing section earns zero for that section even when no cap is listed. Do not infer course completion from a unit pass.

## 1. Numerical contract — 25 points

- **12 points:** 4-bit and 8-bit per-tensor symmetric quantization, scale, clamping, shape preservation, halfway-away-from-zero rounding, and the all-zero policy are correct.
- **5 points:** `matvec` computes correct row dot products for rectangular matrices.
- **5 points:** `quantized_matvec` is numerically equivalent to multiplying by explicitly reconstructed weights and does not rebuild a full float matrix per call.
- **3 points:** required malformed/nonfinite inputs are rejected with `ValueError`, outputs are new lists, and inputs remain unchanged.

Independent anchors:

- For `[[-1.0, -0.5, 0.0, 0.5, 1.0]]` at 4 bits, expect scale `1/7` and integers `[[-7, -4, 0, 4, 7]]`.
- An all-zero matrix retains shape, contains integer zeros, and has scale `1.0`.
- For `matrix=[[1.0, 2.0], [-3.0, 4.0]]` and `vector=[5.0, -2.0]`, `matvec` returns `[1.0, -23.0]`.
- Use tight floating tolerance for reconstruction arithmetic, while deriving expected values outside the submitted helpers.

For the underspecified integer-range check in `quantized_matvec`, accept a coherent documented boundary (for example, signed 8-bit storage) provided it rejects non-integers, validates positive finite scale, and does not claim to recover a bit width that is absent from the API.

## 2. Verification quality — 20 points

- **8 points:** focused tests cover both widths, signs, exact ties, zeros, one-row/one-column shapes, and both linear operators with meaningful independent expectations.
- **5 points:** tests cover every invalid-input family, input non-mutation, and repeat-call determinism.
- **4 points:** a fixed-seed property-style loop spans multiple shapes and checks genuine invariants against an independently expressed oracle.
- **3 points:** tests are isolated, readable, deterministic, and pass with the documented command.

Reduce credit where tests restate implementation helpers, use only loose assertions, swallow broad exceptions, depend on execution order, or omit failure messages that would localize a regression.

## 3. Measurement and result integrity — 20 points

- **5 points:** the benchmark uses seed 65940, the three exact shapes, both widths, shared data per shape, and all six correctly named cases.
- **5 points:** setup is outside timing; each path has at least three warmups, 15 individual measurements, alternating first-run order, `perf_counter_ns`, and a true median.
- **4 points:** maximum/mean absolute output error is recomputable and finite; payload values exactly follow `4N` and `ceil(Nb/8)+4`.
- **3 points:** JSON types, stable case order, CLI output behavior, provenance, actual environment values, and `LEARNER_GENERATED_UNVALIDATED` label meet the schema.
- **3 points:** reproduced deterministic fields agree with the checked-in record, and runtime magnitudes are plausible without requiring a speedup.

Expected payload anchors: for 16 by 32 weights, float32 logical payload is 2048 bytes; packed 4-bit plus one scale is 260 bytes; packed 8-bit plus one scale is 516 bytes.

## 4. Software-engineering judgment — 20 points

- **5 points:** implementation is modular, clear, typed or otherwise explicit at boundaries, and free of unnecessary duplication.
- **5 points:** validation is centralized and consistent; errors are useful; CLI failure is nonzero and does not overwrite unrelated paths.
- **6 points:** `DESIGN.md` accurately records the API, invariants, rounding/range choices, independent-oracle strategy, benchmark controls, and limitations.
- **4 points:** tradeoff claims cite actual cases, distinguish logical serialization from Python memory, and avoid unsupported hardware, compression, or speed claims.

Favor simple inspectable code over abstraction for its own sake. Do not deduct merely because pure Python is slow; interpretation and experimental honesty are the targets.

## 5. Comprehension — 15 points

Award up to 2 points for each response 1–7 and 1 point for response 8. A full-credit response is concise, technically sound, specific to the submission, and answers every clause. Use these anchors:

1. Nearest rounding gives at most half a scale of per-weight error when values are not clipped; a row-output bound can sum `abs(x_j)` times the corresponding weight-error bounds. Ties and assumptions should be acknowledged.
2. A large outlier enlarges the shared scale and coarsens resolution for small weights; useful evidence compares zero counts or reconstruction errors with and without an outlier.
3. The JSON models packed float32/bit payload plus scale, while Python lists, integers, and floats carry object/container overhead and 4-bit values are not automatically packed.
4. The response must cite observed cases. Pure-Python integer objects, conversion/multiplication overhead, absent packed kernels, and the unchanged operation count can explain why payload reduction need not speed execution.
5. Strong controls include shared inputs, excluded setup, warmups, alternating order, individual timings, and medians. Scale multiplication remains in the quantized timed path. Noise, CPU state, interpreter effects, or ordering are reasonable residuals with a concrete mitigation.
6. Accept valid properties such as shape preservation, value bounds, reconstruction agreement, non-mutation, determinism, or an error bound, only when each is tied to a plausible bug and a genuinely separate oracle.
7. A zero maximum otherwise causes division by zero or an invalid scale. The specified sentinel scale keeps serialization finite, the operator zero, validation satisfied, and reruns stable.
8. Per-row scales require a scale vector and shape-aware API/serialization, row-specific reconstruction and validation, revised metadata and payload overhead, and tests for row alignment/zero rows. Adoption needs measured accuracy and cost evidence on representative data.

Do not require wording identical to these anchors. Award alternative correct reasoning when it is supported by the learner's artifacts.
