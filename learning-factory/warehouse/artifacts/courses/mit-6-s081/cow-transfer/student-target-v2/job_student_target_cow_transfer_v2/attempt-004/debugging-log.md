# Debugging hypotheses and proposed experiments

This is an observable debugging plan, not a record of hidden reasoning. Each experiment uses only
the public contract and `stats()` unless it explicitly mentions the test-only invariant checker.

| Hypothesis | Likely symptom | Proposed experiment and expected observation |
|---|---|---|
| Shared mappings are accidentally sent through the private COW path. | An unrelated mapper stops seeing writes, and `frame_count` rises. | Create one name, map it writable in two processes, write from one, and read from the other. Repeat after fork and after unlink. Every read should see the write and the system should retain one frame. |
| Private mappings are accidentally treated as genuinely shared. | A child's write changes the parent's bytes. | Allocate a page, fork, write one byte in the child, and compare full-page reads. Parent bytes must be unchanged; stats must move from one two-owner frame to two one-owner frames. |
| A sticky COW flag causes an unnecessary copy after all other owners leave. | `frame_count` or frame ID changes on a sole owner's first write. | Allocate, fork, exit the parent, snapshot stats, then write in the child. The same single frame ID should remain. |
| COW tests a combined mapping-plus-name count rather than the relevant mapping owners. | Copy behavior is coupled to an unrelated kind of lifetime edge. | Run separate private and named traces while recording both counts. Private copying must depend only on another private mapping; named writes must never clone whether `name_refs` is one or zero. |
| Fork adds child PTEs without all reciprocal frame owners. | Stats undercounts mappings; later child teardown reclaims too early or fails an assertion. | Give a parent several private and shared PTEs, fork, and check that each affected frame's mapping refs rises by exactly one per inherited PTE. Exit parent, access every child PTE, then run the invariant checker. |
| Fork loses read-only permissions. | A child can write through an inherited read-only shared mapping. | Map a segment read-only, fork, and attempt a child write. Expect `ValueError`, unchanged bytes, and unchanged stats. |
| Unlink reclaims by name count alone. | Existing mappings fail after unlink. | Create, map twice, unlink, then read and write through both mappings. The segment count and name refs should be zero while the frame stays live until the second unmap. |
| The final unmap leaks an unlinked frame. | An ownerless frame remains in stats. | Execute create, two maps, unlink, two unmaps and snapshot after each step. After the last unmap, `frame_count` must become zero and the old ID must be absent. |
| Exec or exit releases only some PTEs, or releases one twice. | Mapping refs remain too high, become inconsistent, or a frame disappears while another owner still maps it. | Build one process with multiple private and shared PTEs, sharing some frames with another process. Run exec and then a separate exit case. Compare each frame's exact decrement to the number of removed PTEs and verify surviving mappings remain readable. |
| A failed teardown mutates state before discovering an unknown target. | Counts or bytes change after `KeyError`. | Snapshot stats and all readable bytes, then call unmap on a missing VPN, unlink twice, and exec/exit an unknown PID. Compare the complete observable snapshot before and after each error. |
| Bounds checks mishandle negatives, exact end-of-page accesses, or empty writes. | Python negative slicing succeeds, valid zero-length access fails, or an empty write clones. | Exercise `(-1, 1)`, `(0, -1)` for reads, offsets 4095 and 4096, and every exact/one-byte-past boundary. On a two-owner private frame, perform an empty write and ensure it remains one frame with two owners. |
| Read-only rejection happens after mutation or COW allocation. | Data or frame count changes even though write raises. | Put a read-only named mapping beside a writable one, snapshot bytes and stats, attempt several read-only writes, and require `ValueError` with byte-for-byte and count-for-count equality. |
| Duplicate checks race with insertion. | Both contenders report success, an owner is overwritten, or an orphan frame leaks. | Start two threads at a barrier to allocate the same `(pid, vpn)`; repeat for one name and one child PID. Exactly one call should succeed, one should raise `ValueError`, and the invariant checker should find only one committed object. |
| Map and unlink have a check-then-act gap. | A successful map points to a reclaimed frame. | Race `map_shared` with `unlink_shared` from a barrier for many bounded iterations. Accept either successful map with a live unlinked frame, or unlink-first with map `KeyError` and reclamation; reject every other result. |
| Two simultaneous private writers can both move or delete the wrong owner edge. | Lost writes, an orphan PTE, more than two frames, or incorrect mapping refs. | Fork, barrier-start distinct full-page writes in parent and child, and join with timeouts. Each mapping must contain its own complete pattern; there must be exactly two one-owner frames and reciprocal validation must pass. |
| Shared writes are not atomic at method granularity. | A final page contains a torn mixture of overlapping full-page writes. | Barrier-start two processes writing different repeated-byte full pages to one named frame. The final page must equal one complete pattern. Repeat while a third thread samples reads; every completed read must match a linearized state. |
| Stats reads structures without the state mutex or exposes internal dictionaries. | Counts disagree with owner entries, or caller mutation corrupts later stats. | Sample stats while other threads map and unmap. Each snapshot must be internally consistent. Then mutate every level of one returned snapshot and verify a later snapshot and page data are unchanged. |
| Frame IDs are reused after reclamation. | Logs cannot distinguish an old frame from a new one. | Record an ID, remove its final owner, allocate a new frame, and require a strictly larger ID. Retained frame IDs must remain unchanged across unrelated operations. |
| A lock is omitted on an error or teardown path. | Rare deadlock, exception-dependent race, or a thread never joins. | Mix successful and deliberately failing calls across barrier-synchronized threads, always join with bounded timeouts, and run a final known-good create/read/write sequence plus the invariant checker. |

For any failing experiment, the first diagnostic snapshot should include the operation sequence,
exception types, process/segment/frame counts, each frame's two reference counts, and the relevant
page bytes. That evidence distinguishes a wrong semantic mode from a lost ownership edge without
depending on prose claims.
