# Design questions

Write down answers before reading any post-exercise discussion.

1. What invariant should every expression compiler leave on the operand stack?
2. Where should a forward-jump patch location point: at the opcode or operand?
3. How will your symbol table distinguish shadowing from same-scope duplicate
   declarations?
4. At what moment should a newly declared name become visible to its own
   initializer, and why?
5. How can `&&` and `||` be compiled using only `JZ`, `JMP`, and `PUSH`?
6. Which arithmetic cases are undefined in host C even though their operands
   have valid `int64_t` representations?
7. Should the VM trust local-slot operands generated by your compiler?  What
   future feature makes that decision important?
8. How do you guarantee an instruction budget counts loops consistently when
   some instructions have operand words?
9. What evidence would distinguish bytecode-boundary self-interpretation from
   full source-level self-hosting?
10. Which fixed limits belong in the language contract, and which should be
    configurable deployment policy?
